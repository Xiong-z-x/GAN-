一、项目总目标

本项目有两条主线：

1. 课程实验线：
   - DCGAN / DCGAN++：作为课程基础 GAN baseline 和改进实验。
   - StyleGAN3：作为成熟 GAN 的高质量人像生成上限展示，使用官方 FFHQ 预训练权重。
   - AnimeGANv2 / CycleGAN：作为 GAN 风格迁移和课程扩展模块。
   - FID、可视化图、报告素材：用于形成完整实验报告。

2. 应用封装线：
   - FaceGAN Studio：Gradio Web 程序。
   - 功能包括上传人脸、动漫风格化、造型/姿态生成、轻造型保脸、GFPGAN 后处理、项目成果展示。
   - InstantID 用于输入人脸身份保持生成。
   - GFPGAN 已接入并验证为人脸修复/清晰化后处理，不能写成身份保持模型。

四、必须遵守的事实边界

- DCGAN / DCGAN++ 是 baseline，画质有限是合理结果。
- StyleGAN3 是官方预训练权重复现，不是本项目从零训练。
- AnimeGANv2 / CycleGAN 是风格迁移增强，不参与 DCGAN FID 主表排序。
- InstantID 是 identity-preserving diffusion 应用扩展，不是 GAN。
- GFPGAN 只能写作后处理增强，不负责身份保持。
- StyleGAN2-ADA 人脸反演 + 潜空间编辑已取消作为当前交付模块，原因是短时间短步数身份偏差明显。
- 轻造型保脸结果使用关键点叠加眼镜，不重绘五官，不属于 GAN 或 InstantID 训练成果。
- 个人照片只用于本人课程演示，不进入训练集，不提交公开仓库。
- `GAN_results_images/`、`GAN_new_showcase_results/`、`outputs/`、`data/`、`external/`、权重文件不应整体提交 GitHub。
- `docs/handoff_assets/` 是少量代表图，适合随 GitHub 同步。

五、AutoDL 环境原则

AutoDL 后续主要通过 Remote-SSH 操作，源码通过 GitHub 更新。不要反复打包传输整个项目。

InstantID 运行前必须确认：

```text
external/InstantID/checkpoints/ControlNetModel/diffusion_pytorch_model.safetensors
external/InstantID/checkpoints/ip-adapter.bin
external/InstantID/models/antelopev2/
INSTANTID_BASE_MODEL_DIR 或 /root/autodl-fs/models/YamerMIX_v8
```

历史上 Hugging Face 在线拉取出现过低速和 503。推理阶段必须优先使用本地模型路径和 `local_files_only=True`，不要让 Web 程序临时下载 SDXL 大模型。

不要直接安装 InstantID 官方 demo requirements 覆盖当前 PyTorch 环境；如需修依赖，先记录当前 `torch`、`torchvision`、`diffusers`、`transformers`、`huggingface_hub`、`accelerate` 版本，再做最小修复。

七、验证原则

你不能因为“看起来差不多”就认定完成。每个关键输出必须验证：

- 文件是否存在
- 数量是否合理
- 图像是否能打开
- 输出目录是否正确
- 是否覆盖旧结果
- 是否能写入报告素材目录
- 是否有错误日志

如果结果不好，就说明还不够好。不要自我安慰式结束；应重新判断是模型上限、参数问题、输入质量问题、依赖问题还是路径问题。

八、文档维护原则

每次新踩坑、新修复、新结果都要写入文档，不要只写在聊天里。

优先更新：

- `docs/handoff/后续模型注意事项.md`
- `AutoDL_运行指南.md`
- `FaceGAN_Studio_运行说明.md`
- `代码附录.md`
- `报告素材使用说明.md`

遇到不确定性时，必须明确标注：

- 事实：已经用命令或文件验证。
- 推断：基于事实做出的判断。
- 待验证：还没有实际跑通。
