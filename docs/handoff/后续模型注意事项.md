# 后续模型注意事项

本文写给后续接手的新对话模型。它记录本项目最容易误判和踩坑的地方，优先级高于旧聊天记忆。

## 1. 最容易犯错的地方

### 1.1 把不同模型定位混在一起

正确边界：

- DCGAN / DCGAN++：课程 baseline 和改进实验。
- StyleGAN3：官方 FFHQ 预训练权重，高质量 GAN 上限展示。
- AnimeGANv2 / CycleGAN：风格迁移增强模块。
- InstantID：身份保持 diffusion 应用扩展。
- GFPGAN：后续可选人脸修复模块，当前不能写成已完成。

错误做法：

- 把 InstantID 说成 GAN。
- 把 AnimeGANv2/CycleGAN 纳入 DCGAN FID 排序。
- 把 StyleGAN3 官方预训练说成自己训练。
- 把 DCGAN 画质不足解释成“还差一点训练”而持续无目标消耗 GPU。

### 1.2 把历史结果当成当前文件事实

本项目历史很长，路径和输出目录多次变化。接手后必须先查真实文件：

```bash
pwd
git status --short
find outputs -maxdepth 2 -type f | wc -l
find report/report_assets -type f | wc -l
find docs/handoff_assets -type f
```

不要直接相信旧对话中的“已经完成”“文件在某目录”“数量是多少”。

### 1.3 监控脚本盯错目录

DCGAN 续训时曾出现“看起来卡住”的情况，真实原因可能是监控脚本仍读取旧目录。每次恢复训练都要确认：

- 当前训练命令的 `--output-dir`
- loss_history.jsonl 是否在更新
- checkpoint 是否在当前目录写入
- 监控脚本是否读取同一个目录

### 1.4 Hugging Face 下载和依赖版本

InstantID 历史问题主要来自：

- 大模型在线拉取慢或 503。
- `huggingface_hub`、`accelerate`、`diffusers` 版本不兼容。
- 官方 demo requirements 强制改 PyTorch，破坏原环境。

后续原则：

1. 大模型先本地 snapshot，再推理。
2. 推理阶段使用 `local_files_only=True`。
3. 不要盲目升级/降级 torch。
4. 优先验证：

```text
external/InstantID/checkpoints/ControlNetModel/diffusion_pytorch_model.safetensors
external/InstantID/checkpoints/ip-adapter.bin
external/InstantID/models/antelopev2/
INSTANTID_BASE_MODEL_DIR 或 /root/autodl-fs/models/YamerMIX_v8
```

### 1.5 GitHub 不适合保存大结果

不能提交：

- `GAN_results_images/`
- `GAN_new_showcase_results/`
- `outputs/`
- `data/`
- `external/`
- `.pth/.pt/.pkl/.ckpt/.onnx`
- 个人照片

需要让 AutoDL 从 GitHub 看到代表成果时，只使用：

```text
docs/handoff_assets/
```

## 2. 接手后必须先确认的事项

### 2.1 本地或 AutoDL 当前目录

```bash
pwd
git branch --show-current
git status --short
git remote -v
```

### 2.2 AutoDL 模型资源是否存在

```bash
ls -lh external/InstantID/checkpoints/ControlNetModel/diffusion_pytorch_model.safetensors
ls -lh external/InstantID/checkpoints/ip-adapter.bin
find external/InstantID/models/antelopev2 -type f | sort
ls -lh /root/autodl-fs/models/YamerMIX_v8/model_index.json 2>/dev/null || true
```

### 2.3 外部仓库是否存在

```bash
test -f external/stylegan3/gen_images.py && echo stylegan3-ok
test -f external/animegan2-pytorch/test.py && echo animegan-ok
test -f external/pytorch-CycleGAN-and-pix2pix/test.py && echo cyclegan-ok
test -f external/InstantID/pipeline_stable_diffusion_xl_instantid.py && echo instantid-ok
```

## 3. 文档原则

每次新增实验或修复后都要写入文档，不要只留在聊天里。

推荐更新位置：

| 情况 | 更新文档 |
|---|---|
| 新的整体状态 | `docs/handoff/迁移前交接总报告.md` 或新建阶段报告 |
| 新踩坑或修复经验 | `docs/handoff/后续模型注意事项.md` |
| 新运行流程 | `AutoDL_运行指南.md` |
| 新代码模块 | `代码附录.md`、`文件说明.md` |
| 新素材 | `报告素材使用说明.md` |
| 新报告章节 | `GAN_真实人像生成实验报告.md` |

写文档时必须区分：

- **事实**：当前文件、命令输出、真实生成结果。
- **推断**：基于现象的技术判断。
- **待验证**：还没有实际运行验证的内容。

## 4. 后续开发原则

1. 先验证环境，再跑重模型。
2. 先跑小样本，再放大生成数量。
3. 每次重跑使用新输出目录，不覆盖旧结果。
4. 失败后定位真实错误，不要换一个更大的模型掩盖问题。
5. 结果不好就承认不好，继续找更稳策略或调整报告定位。
6. 不要把“能导入”当成“功能已跑通”。
7. 不要把“脚本执行完成”当成“结果可用于报告”，必须检查输出图质量。
8. 不要把用户个人照片加入公开训练集或公开仓库。

## 5. FaceGAN Studio 后续最小验证顺序

在 AutoDL 上执行：

```bash
cd /root/autodl-tmp/GAN
python -m compileall src scripts facegan_studio
python -m facegan_studio.app --help
bash scripts/run_facegan_studio.sh
```

然后按页面验证：

1. 项目成果展示页能加载 `docs/handoff_assets/`。
2. 上传图能生成检测预览。
3. 证件照模块能输出三张图和拼图。
4. AnimeGANv2 三权重能输出。
5. CycleGAN 可选输出能生成。
6. InstantID 先生成 4 张，再扩到 8/16 张。

## 6. 报告写作注意

报告应采用递进叙事：

1. DCGAN：从零手写，体现课程基本原理。
2. DCGAN++：尝试稳定化和结构增强，诚实呈现改善与限制。
3. StyleGAN3：成熟 GAN 上限展示。
4. AnimeGANv2/CycleGAN：GAN 风格迁移应用。
5. InstantID/FaceGAN Studio：输入人脸身份保持应用封装，作为最终系统展示。

不要把所有模块硬说成同一个模型的不同版本。每个模块都要说明数据来源、权重来源、是否自己训练、是否只做推理。

## 7. 上下文变长后的防失真方法

后续每完成一个阶段，立即更新一个短状态文档，建议格式：

```text
docs/handoff/阶段状态_YYYYMMDD_<主题>.md
```

内容必须包含：

- 本轮真实执行命令。
- 输出目录。
- 成功文件数量。
- 失败命令和错误摘要。
- 哪些结论是事实，哪些只是推断。
- 下次接手第一步应该做什么。

这样可以避免新模型依赖长聊天历史后产生路径错乱和伪完成判断。
