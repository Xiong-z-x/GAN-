# 后续模型注意事项

本文写给后续接手的新对话模型。它记录本项目最容易误判和踩坑的地方，优先级高于旧聊天记忆。

## 1. 最容易犯错的地方

### 1.1 把不同模型定位混在一起

正确边界：

- DCGAN / DCGAN++：课程 baseline 和改进实验。
- StyleGAN3：官方 FFHQ 预训练权重，高质量 GAN 上限展示。
- AnimeGANv2 / CycleGAN：风格迁移增强模块。
- InstantID：身份保持 diffusion 应用扩展。
- GFPGAN：后续可选人脸修复模块，当前不能写成已完成。

错误做法：

- 把 InstantID 说成 GAN。
- 把 AnimeGANv2/CycleGAN 纳入 DCGAN FID 排序。
- 把 StyleGAN3 官方预训练说成自己训练。
- 把 DCGAN 画质不足解释成“还差一点训练”而持续无目标消耗 GPU。

### 1.2 把历史结果当成当前文件事实

本项目历史很长，路径和输出目录多次变化。接手后必须先查真实文件：

```bash
pwd
git status --short
find outputs -maxdepth 2 -type f | wc -l
find report/report_assets -type f | wc -l
find docs/handoff_assets -type f
```

不要直接相信旧对话中的“已经完成”“文件在某目录”“数量是多少”。

### 1.3 监控脚本盯错目录

DCGAN 续训时曾出现“看起来卡住”的情况，真实原因可能是监控脚本仍读取旧目录。每次恢复训练都要确认：

- 当前训练命令的 `--output-dir`
- loss_history.jsonl 是否在更新
- checkpoint 是否在当前目录写入
- 监控脚本是否读取同一个目录

### 1.4 Hugging Face 下载和依赖版本

InstantID 历史问题主要来自：

- 大模型在线拉取慢或 503。
- `huggingface_hub`、`accelerate`、`diffusers` 版本不兼容。
- 官方 demo requirements 强制改 PyTorch，破坏原环境。

后续原则：

1. 大模型先本地 snapshot，再推理。
2. 推理阶段使用 `local_files_only=True`。
3. 不要盲目升级/降级 torch。
4. 优先验证：

```text
external/InstantID/checkpoints/ControlNetModel/diffusion_pytorch_model.safetensors
external/InstantID/checkpoints/ip-adapter.bin
external/InstantID/models/antelopev2/
INSTANTID_BASE_MODEL_DIR 或 /root/autodl-fs/models/YamerMIX_v8
```

### 1.5 GitHub 不适合保存大结果

不能提交：

- `GAN_results_images/`
- `GAN_new_showcase_results/`
- `outputs/`
- `data/`
- `external/`
- `.pth/.pt/.pkl/.ckpt/.onnx`
- 个人照片

需要让 AutoDL 从 GitHub 看到代表成果时，只使用：

```text
docs/handoff_assets/
```

- **事实**：当前文件、命令输出、真实生成结果。

- **待验证**：还没有实际运行验证的内容。

## 4. 后续开发原则

1. 先验证环境，再跑重模型。
2. 先跑小样本，再放大生成数量。
3. 每次重跑使用新输出目录，不覆盖旧结果。
4. 失败后定位真实错误，不要换一个更大的模型掩盖问题。
5. 结果不好就承认不好，继续找更稳策略或调整报告定位。
6. 不要把“能导入”当成“功能已跑通”。
7. 不要把“脚本执行完成”当成“结果可用于报告”，必须检查输出图质量。
8. 不要把用户个人照片加入公开训练集或公开仓库。

### 8.3 AutoDL 本机访问 Gradio 要避开代理

### 8.4 CycleGAN 下载脚本不能覆盖已有权重

旧 `scripts/run_cyclegan_pretrained_style.sh` 会无条件调用官方 `download_cyclegan_model.sh`，该脚本使用 `wget -O latest_net_G.pth`。如果网络中断，会把原本可用的 checkpoint 覆盖成不完整文件。

本轮已修复为：

- 本地 checkpoint 达到大小阈值时直接复用。
- 缺失或不完整时下载到 `.download` 临时文件。
- 下载完成且大小合理后再替换正式 checkpoint。

对应回归测试：

```bash
python -m unittest tests.test_facegan_studio_core.FaceGANStudioCoreTests.test_cyclegan_script_reuses_existing_checkpoint -v
```

### 8.5 报告素材复制要处理同名文件

- `/root/.vscode-server/data/Machine/settings.json`

- `/root/.cursor-server/data/Machine/settings.json`

复查命令：

```bash
rg -n "17890|17891|NO_PROXY|no_proxy|noProxy|http\\.proxy" \
  /root/.codex_proxy_env \
  /root/.vscode-server/server-env-setup \
  /root/.cursor-server/server-env-setup \

  /root/.vscode-server/extensions/openai.chatgpt-26.429.30905-linux-x64/bin/linux-x86_64/codex \

  /root/.vscode-server/data/User/settings.json \

  /root/.vscode-server-insiders/data/User/settings.json \
  /root/.cursor-server/data/Machine/settings.json \
  /root/.cursor-server/data/User/settings.json
```

当前验证结果：

- 上述固定文件未再出现 `17890`，均指向 `17891`。
- `/proc/net/tcp` 显示 `0100007F:45E3` 处于 `0A` 监听状态，即 `127.0.0.1:17891` 正在监听；未看到 `17890` 监听。
- 监听 socket `4154607154` 属于 `sshd: root@notty`，说明当前 SSH `RemoteForward` 已建立。
- `curl -I -sS --max-time 20 https://chatgpt.com/backend-api/codex/responses` 返回 `HTTP/1.1 200 Connection established` 和 `HTTP/2 405`，其中 `405` 是因为用 HEAD 请求测试，真实 Codex 请求使用 POST / WebSocket。
- 如果 VS Code “端口”面板仍显示 `17890`，先以远程内核状态为准。2026-05-07 复查时，面板显示 `sshd: root@notty (9980)`，但远程 `/proc/9980` 已不存在，`/proc/net/tcp` 和 `/proc/net/tcp6` 均无 `17890`，且 `curl --proxy http://127.0.0.1:17890 ...` 返回 `Connection refused`。这种情况是 VS Code 旧自动转发条目或旧窗口状态，不代表当前远程代理仍在使用 `17890`。

如果 Windows 本机 VS Code 仍提示“无法与 autodl-gan 建立连接”，优先检查本机 `~/.ssh/config` 的 `Host autodl-gan` 是否仍残留 `17890`，并在 VS Code 执行 `Remote-SSH: Kill VS Code Server on Host...` 后重连。
